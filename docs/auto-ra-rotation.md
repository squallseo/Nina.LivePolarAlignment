# Automatic RA rotation

Version 0.1.0.62 begins deceleration with at least 1.5 seconds of high-speed travel plus one degree of headroom (minimum five degrees), rather than waiting for the last five degrees at every rate. The time budget includes this longer slow section. Return verifies its saved mechanical hour angle and, for residuals between 0.5 and 5 degrees, permits at most two guarded corrections at no more than 0.25 degree/second. Device, Dec, pier side and measured motion direction remain checked, and the final 0.5-degree position tolerance is unchanged. This addresses the field-observed 4.629-degree return overshoot; arbitrary or unbounded retries are not used.

Version 0.1.0.59 accounts for one-second ASCOM coordinate bursts even when small model updates occurred between full position updates. An individual burst and cumulative travel are both bounded against the commanded speed; reversal, invalid state, Dec/pier changes and missing motion still stop. The actual 0.1.0.58 field run passed three-position axis consistency (36.546 arcsec) but stopped during RA return on the old jump heuristic. Raw frames and telemetry were retained for replay.

`Auto RA rotation` prepares the mount (including Unpark when required), then captures the first reference. Once its raw data and quick-look preview are available, first-image solving and RA rotation run concurrently. Both must succeed, including verified stop and settling, before the second reference capture. Once both solutions establish the RA axis, the mount returns along the opposite RA direction to the starting position, stops and settles, and captures a fresh solved adjustment reference before continuous live measurement. It defaults on and retains the selected mode across connection changes, cancellation, and failures. While Auto is selected, unavailable mount prerequisites disable Start before calibration; they never silently change the selection. Switch Auto off explicitly to use camera-only manual calibration. After calibration, live measurement requires only the camera. In manual mode, Start captures only the first reference and displays an explicit RA-rotation prompt. Rotate RA, then press Continue; continuous live measurement starts automatically after that reference. The user adjusts altitude and azimuth bolts during live measurement.

## Settings and prerequisites

- Connect the camera in N.I.N.A. Equipment; with Auto selected, also connect a supported mount to enable calibration Start. Manual polar alignment requires only the camera; automatic RA rotation additionally requires a connected, supported mount. Missing camera and mount connections use N.I.N.A.'s red circled-X indicator and a compact Not connected label beside Start and Auto RA respectively. Connected indicators are hidden; details appear on hover. Rotation settings collapse when Auto RA is off. Configure the solver, site, focal length, and pixel size, then point near the visible celestial pole.
- A connected equatorial mount must support RA `MoveAxis`, tracking on/off control, and a supported RA manual movement speed of at least 0.1°/s selected in N.I.N.A. mount controls. Stop other sequences, guiding, and manual movement.
- Rotation defaults to 90°. Available angles are 60°, 70°, 80°, and 90°; remeasurement uses the same setting.
- Version 0.1.0.58 reverses the initial direction to NINA E / positive RA after the user observed W / negative RA moving clockwise on the actual setup. Reverse defaults off in both calibration and verification; the icon shows counterclockwise for this default. PrimaryReversed=false is retained, and the return uses the opposite command. The stock PoleMaster preset uses two 40-degree intervals, total 80 degrees, independently of the general 60/70/80/90-degree setting. Physical appearance depends on viewing side; the updated direction still needs field confirmation.
- Check clearance for the selected direction, full rotation, and stopping margin, including the telescope, tripod, and cables. Remeasurement also rotates and returns from its current position; check clearance for both legs.

## Movement and stopping

Calibration reference rotation moves only RA and does not issue GoTo, sync, or Park. In PoleMaster mode, the separate explicit Home/restart action (0.1.0.51+) uses the mount FindHome command and may move both RA and Dec; it waits for a new Polaris click before calibration. After successful automatic calibration it returns RA to the saved starting hour angle (sidereal time minus RA). It temporarily disables tracking and uses the RA manual movement speed selected in N.I.N.A. (`ITelescope.PrimaryMovingRate`), limited to the supported driver ranges. The selected rate is frozen when rotation starts; changing the host setting during movement does not change the active command. The previous real-mount 1°/s cap and simulator-only 4°/s exception have been removed. Final-five-degree deceleration (up to 0.5°/s where supported), feedback checks, cancellation, verified stopping, and tracking restoration still apply. RA coordinates are unwrapped across the 24-hour boundary to accumulate rotation. Axis estimation uses the rotation measured from the two images.

The primary button shows a play icon before starting. During reference capture or RA rotation it becomes a stop icon with Cancel; during live measurement it shows Stop. The same button requests cancellation, shows Stopping while cleanup runs, and returns to its next start/resume action only after cleanup. Reset is a separate compact icon button. Closing or hiding the panel also requests cancellation. The plugin sends zero speed, checks stop feedback, and restores the original tracking state. It waits two seconds before the second capture. If stopping fails, it attempts an abort, reports the error, and does not re-enable tracking without confirmation from the driver.

No movement response for six seconds, or exceeding the overall timeout, stops the operation. Connection, Dec, pier-side changes, and abnormal coordinate changes also stop it. Failed or cancelled rotation or return discards calibration. A stopped or failed operation never starts an automatic recovery movement. Return is attempted only after both references solve and calibrate successfully. If rotation completes but only the second solve fails, recapturing does not repeat the rotation.

## Rotation range and validation

The [SharpCap Polar Alignment guide](https://docs.sharpcap.co.uk/4.1/9_PolarAlignment.htm) is the reference for approximately 90° rotation and a 60–80° alternative when considering obstructions and flexure. Smaller rotations are more sensitive to the same orientation error; equivalent precision at 60° and 90° is not assumed. Use the default 90° when clearance permits.

Mock-device tests and synthetic WPF previews cover the workflow. Physical mount movement, stopping, and accuracy remain unverified. The plugin provides no collision avoidance or mechanical-limit detection and cannot fully detect incorrect driver stop feedback. Debug recording saves rotation events and reference images in the session.

The Auto RA tooltip names the failing prerequisite, including parked or moving mounts, non-equatorial mode, missing RA/tracking control, unsupported speed, and invalid coordinates. When Auto RA is selected, Start uses N.I.N.A.'s Unpark operation if needed and verifies that the same mount is unparked and ready before the first exposure. Unpark failure or cancellation prevents capture. Manual mode never requests Unpark. Captured image previews appear before solving; axis guidance is displayed only after a successful solution.

The primary button uses short labels (Start, Continue, Resume; Cancel or Stop while working). Preparation/Unpark, reference capture, solving, and RA rotation progress are sent through `IApplicationStatusMediator` to N.I.N.A.'s application status bar at the bottom of the main window. Unpark uses the host mediator so N.I.N.A.'s own refusal conditions still apply. No GoTo or automatic return/parking is added.

The plugin control panel does not repeat operation status in its heading or below the alignment card. The host status entry uses one stable source and clears when the operation ends or the panel is disposed. Manual RA-rotation instructions remain in the host status bar while waiting for Continue.

## Preview latency

Single exposures use N.I.N.A. CaptureImage without waiting for its full image preparation/statistics pipeline. After raw decoding, a reduced grayscale quick-look image is published and the WPF render queue is given a turn before full-resolution ASTAP work runs on a worker thread. A separate display stretch does not modify raw pixels used for solving or saved evidence. When the solve completes, the full-resolution display and computed overlay are published; optional evidence saving does not delay the reference overlay. Timing markers in the N.I.N.A. log distinguish download, first preview, solve, and full-resolution display.

## Overlapping first solve and RA rotation

Automatic calibration freezes the first image, capture midpoint, and solver search coordinates before movement begins. Analysis uses those saved pixels while the mount rotates. A failure in either analysis or rotation cancels the sibling task; both tasks and mount stop verification finish before the operation returns or another capture can start. A failed or cancelled combined operation discards calibration. Manual capture remains sequential.

The first image stays visible during rotation. The Streaming option starts native video only after the two calibration references, during live adjustment; it does not provide a continuously refreshed video preview during calibration or rotation. Native streaming supports QHY, ZWO ASI and ToupTek drivers; unsupported drivers fall back to single-frame measurement.

Preview delivery and the freshness timer explicitly use the host application UI Dispatcher. N.I.N.A. composes plugins on a background loader thread; its unpumped Dispatcher must not receive image updates. The standalone workflow check also constructs the VM on a background thread to cover this host loading behavior. Logs record when each preview is applied to the UI, separately from raw download and solver timings.

When the first solve succeeds during rotation, its full-resolution reference preview, celestial-pole marker, and angular guide rings are published immediately. They refer to the saved first image, not the current moving field. The RA-axis marker and alignment error still require the second solved reference. Publishing the first overlay does not complete calibration or release the capture/motion reservation.

Rotation reduces speed within the final five degrees when the driver supports a lower rate (up to 0.5 degrees/s). Status progress is capped at the selected target; the actual feedback angle, including any polling overshoot, is retained in recording. Stop verification and settling still precede the second capture. DIRECTORY camera simulation requires a changed scene for the second reference; the simulator tool documents a persistent angle-aware reference-feed helper.

During calibrated live measurement, the last solved image, matching geometry overlay, and error readout remain visible while the next still frame is analyzed. Native streaming instead publishes current-frame star tracking, with live preview and cleared overlays during tracking recovery. A successful result replaces them together. Initial calibration still publishes quick-look pixels immediately. Stop, failure, and the existing freshness timeout continue to invalidate guidance; receiving an unsolved preview does not refresh a measurement timestamp.

The image canvas does not draw capture, solving, or reference-wait progress text. These messages belong exclusively to the host application status bar. Unsolved or stale images retain their existing visual dimming, and astrometric marker labels remain visible when valid.

A solved first-reference image and its pole/rings remain visible during second-reference analysis, just as solved measurement displays remain visible during subsequent live analysis. Automatic-mode errors use Retry rather than the manual Continue label. A second-solve retry reuses the completed rotation; a cancelled/failed rotation discards calibration and starts from a new first reference. UI regression covers one-Start completion at all four angles in both directions, second-reference overlay retention, and retry without repeated rotation.

Measurement age does not hide the last solved image, rings, or detail canvas. Display availability is independent of freshness: stale quality remains unavailable, while its matching saved image/overlay stays in place until a new successful solve replaces it. The freshness budget also accounts for the observed capture/solve cycle (three cycles plus five seconds), preventing a normal slow solver from repeatedly crossing a fixed 15-second deadline. Stop, failure, reset, or explicit mode changes may still invalidate guidance. Slow-cycle UI regression crosses the former 15-second threshold and the extended stale threshold in both still and streaming modes.

## Live-solve search hints

After a successful plate solution, single-frame and native streaming acquisition use that solution as the next search hint. Still frames are solved independently. Native streaming tracks stars against an absolute reference and refreshes that reference with background ImageSolver verification. See streaming-review.md for confidence and recovery limits. The cached position never supplies alignment measurements. Hints are scoped to profile, camera, focal length, and pixel size; Reset clears them and they expire after ten minutes. Initial capture still uses the mount hint or blind solver.

A production-pipeline regression with full-resolution QHY600 catalog images and deliberately incorrect mount coordinates took 9.898 seconds for the initial blind fallback, then 2.109-2.379 seconds per subsequent frame using solved hints. This replay includes decoding, preview, solver file preparation, ASTAP, and display preparation, but excludes physical camera exposure/download latency. The test also rechecks the reference angle and all five correction stages. It does not promise a hardware frame rate.

## Return before adjustment (0.1.0.40)

The saved start and end positions belong to the same connected mount. Return uses hour angle rather than a fixed celestial RA value, accounting for Earth rotation between captures. It reverses the outgoing command and checks the first nonzero coordinate change against the expected return direction. It refuses a changed mount, Dec, pier side, or a position more than one degree from the completed calibration endpoint. The origin is consumed before movement so a cancelled or failed return cannot be repeated against an old starting point. Feedback, timeout, cancellation, stop verification, tracking restoration, and settling apply to both legs. The final hour angle must be within 0.5 degrees of the saved starting position; this is a positioning tolerance, not a polar alignment accuracy claim.

After returning, the plugin solves a new image and rebases the adjustment camera orientation while preserving the RA axis already estimated in the local horizon. Outbound image displacement or return overshoot is not counted as an altitude/azimuth correction. Until this succeeds, old guidance is invalid and live adjustment cannot begin. A second-reference solve failure stays at the rotated position for Retry and does not trigger an uncalibrated return. Manual mode remains manually positioned. Automated tests cover returned-camera geometry in both hemispheres and parities; the standalone UI checks outward/return sequences for all four angles in both directions. Physical return behavior remains to be validated on hardware.
